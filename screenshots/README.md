# Visual regression

Screenshots of the running app at the three standard viewports.
Used to verify CSS/template changes don't regress the layout, and
to do before/after diffs when investigating reported layout issues.

## Layout

```
screenshots/
├── baseline/   — the "known good" state. CHECKED IN.
│                 Update with `make screenshot-baseline` after
│                 a visual change is reviewed and approved.
├── actual/     — the current run. Gitignored.
│                 Generated by `make screenshot`.
└── diff/       — output of `make screenshot-diff`. Gitignored.
                  Contains <viewport>-diff.png (per-pixel diff
                  in red) and <viewport>-side-by-side.png
                  (before | diff | after, stacked) plus
                  summary.json with diff stats.
```

## Standard viewports

| Name              | Size       | Use                    |
|-------------------|------------|------------------------|
| `desktop-1920x1080` | 1920×1080 | ultrawide / 4K check   |
| `laptop-1280x800`   | 1280×800  | standard laptop        |
| `tablet-768x1024`   | 768×1024  | tablet portrait        |

If a layout change should specifically target a non-standard
viewport, pass it as additional args to `node scripts/screenshot.mjs`.

## Workflow

**Before/after verification** (when a user reports a layout bug):

```bash
# 1. Server is already running. Capture the current (broken) state.
make screenshot
make screenshot-before        # snapshots to screenshots/before/

# 2. Make the fix.
$EDITOR internal/web/static/chat.css  # or wherever

# 3. Rebuild CSS (if you changed templates or CSS sources) and re-capture.
make css
make screenshot

# 4. Diff. The diff directory has the red pixel-diff and a
# side-by-side composite for human review.
make screenshot-diff
open screenshots/diff/desktop-1920x1080-side-by-side.png
```

**Promote to baseline** (after a visual change is reviewed and approved):

```bash
make screenshot-baseline
git add screenshots/baseline/
git commit
```

**CI gate** (optional, if/when a `screenshot-diff` job is added):

The `make screenshot-diff` target exits non-zero when the actual
screenshots differ from the baseline. Wire it as a CI job that
runs after `make screenshot` and fails the build on exit-1.

## How the diff works

`scripts/screenshot-diff.mjs` uses [`pixelmatch`](https://github.com/mapbox/pixelmatch)
to compare the baseline and actual PNGs pixel-by-pixel with a
small antialiasing tolerance (0.1). Each differing pixel is
coloured red in the output. The side-by-side composite stacks
the three panels vertically on a neutral grey gutter so the
human reviewer can see baseline | diff | actual in one image.

The diff's `summary.json` records `diffPx` / `totalPx` / `diffPct`
per viewport. A small diff (sub-1%) is usually benign — a font
load timing difference or an animation that didn't quite settle.
Large diffs (5%+) are a real layout change.
